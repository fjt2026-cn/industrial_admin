## 12 前端业务页面实现

上一章完成了“能登录、能带令牌、能统一处理错误”的基础设施，本章把三个真正的业务页面接上：主布局把菜单与路由绑定，用户管理页把列表、表单、删除与口令重置做成一条完整流程，角色授权页把权限点树与该角色的权限集合对上，运营看板把统计接口的数据画成图。四个页面的共同点是不在页面里拼 URL、不手工加令牌、不各自处理错误——这些都在上一章的 request.js 里统一处理，页面只负责“取数—渲染—交互”。

### 12.2 主布局与侧边栏路由

**布局思路：**布局用 el-container 拆成“侧边栏 + （页头 + 主区）”的结构，菜单开启 router 模式，菜单项的 index 直接写路由路径，点击即跳转，不再额外写 click 事件做 router.push，这样菜单与路由表只有一份事实来源。当前高亮项取 route.path，子路由天然匹配父菜单。侧边栏折叠用一个布尔量控制宽度（200px ↔ 64px），折叠后菜单自动只留图标位置，主区随之变宽。

**页头与退出：**页头左侧是折叠按钮与当前路由标题（取 route.meta.title，页面自己不用再写标题），右侧显示当前登录人姓名并给出“退出登录”。退出前弹一次确认（避免误点），确认后清掉 token、user、permissions、menus 四项本地存储并跳回登录页；只清 token 会留下过期用户信息，下次进页面页头会显示上一个人。

### 12.3 用户管理页

**页面结构：**页面自上而下三块：查询卡片（关键字 + 状态 + 查询/重置/新增）、表格卡片（列表 + 分页）、两个弹窗（新增/编辑共用一个大弹窗，重置口令单独一个小弹窗）。查询参数放在一个 reactive 对象里，关键字回车即查，重置会把页码拉回第 1 页——否则在第 3 页点重置会得到“空列表”，这是分页页面最常见的坑。

**表格渲染：**列依次为 ID、账号、姓名、所属部门、角色、邮箱、手机号、状态、创建时间、操作。角色列用 el-tag 循环渲染角色名（未分配时显示灰色“未分配”），状态列按 1/0 渲染成“启用/停用”两种颜色的标签，时间列把后端返回的 RFC3339 字符串格式化成“年-月-日 时:分”（后台列表不需要秒）。操作列固定在最右侧，避免表格横向滚动时按钮跟着滚走。

**弹窗设计：**新增与编辑复用一个弹窗，差异用 isEdit 判断：新增显示账号与口令，编辑显示状态单选、账号输入框禁用（账号是登录标识，改了会让本人登不进）。校验规则写在 el-form 的 rules 里（账号 2–50 位、口令 6–32 位、姓名必填），提交前 await validate() 不通过就直接返回，不发无意义的请求。

**表2 用户表单字段与校验规则**

| 字段 | 前端规则 | 提交与后端配合 |
| :--- | :--- | :--- |
| 账号 | 必填；2–50 位；新增可填，编辑时禁用 | 后端再做一次长度与唯一性校验，前端只是提前拦截 |
| 口令 | 必填；6–32 位；新增与重置口令使用 | 后端按 bcrypt 哈希后入库，接口入参上限 72 字节 |
| 姓名 | 必填 | 写入 user.real_name |
| 所属部门 | 选填；下拉取自 /depts/tree，按层级缩进 | 传 deptId，空值时提交 null |
| 角色 | 选填、可多选 | 提交 roleIds 数组，后端事务整体替换 user_role |
| 邮箱/手机号/备注 | 选填 | 不做格式强校验，避免与后端规则重复 |
| 状态 | 编辑时单选启用/停用 | 停用后无法登录，由后端登录逻辑拦截 |

**角色回显的处理：**后端用户列表返回的 roles 是角色名称数组，而提交时需要 roleIds（数字）。页面用角色列表接口把名称映射成 id，所以编辑打开时会出现“名称先到、id 后到”的时序问题：如果角色下拉还没加载完就填 id，会得到空数组，保存时就把该用户的角色清空了。这里的做法是先用当前已加载的角色映射一遍，若一个都没匹配上再异步补加载一次角色列表重新映射，宁可多一次请求，也不冒“误清空角色”的风险。

```vue
async function onSubmit() {
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return

  saving.value = true
  try {
    if (isEdit.value) {
      await updateUser(editingId.value, {
        realName: form.realName,
        email: form.email,
        phone: form.phone,
        deptId: form.deptId ?? null,
        status: form.status,
        remark: form.remark,
        roleIds: form.roleIds
      })
      ElMessage.success('修改成功')
    } else {
      await createUser({
        username: form.username.trim(),
        password: form.password,
        realName: form.realName,
        email: form.email,
        phone: form.phone,
        deptId: form.deptId ?? null,
        remark: form.remark,
        roleIds: form.roleIds
      })
      ElMessage.success('新增成功')
    }
    dialogVisible.value = false
    load()
  } catch (e) {
    // 错误提示由拦截器统一弹出（如账号已存在 409）
  } finally {
    saving.value = false
  }
}
```

**删除与口令重置：**删除前用 ElMessageBox 二次确认并显示目标人姓名；账号为 admin 的行删除按钮直接禁用，与后端“内置管理员不可删”的约束在界面上对齐（前端禁用只是提示，真正的拦截仍在后端）。重置口令单独开小弹窗，只显示账号与新口令两项，前端先判长度再提交，成功后用户的其他编辑状态不受影响。

**部门下拉：**/depts/tree 返回的是嵌套树，el-select 需要平铺列表，所以页面用一个递归函数 flattenDept 把树拍平，并按层级在前面补全角空格做视觉缩进。这样既保留了层级信息，又不需要引入额外的树形下拉组件。

### 12.4 角色权限分配页

**页面结构：**上半部分是角色表格（ID、角色名称、编码、数据范围、是否内置、状态、备注、操作），操作列只有“分配权限”一个入口；点击后打开 el-drawer 抽屉，抽屉里放权限树与已选统计。选抽屉而不是再开一个弹窗，是因为权限点有 22 条、分组后更长，抽屉可以给到更高的可视高度，也不遮挡左侧角色列表，管理员能随时确认自己在给哪个角色授权（抽屉标题里带角色名）。

**权限树的分组：**权限表没有 parent_id 字段，做不出真正的父子级联树，因此按 permType 分三组：1 菜单、2 按钮、3 接口，每组下挂该类型的权限点叶子，叶子显示“权限名称（权限编码）”。叶子节点的 key 用 p-<id> 前缀，避免与分组节点（g-menu 等）的 key 混淆；分组节点只承担“分类展示”的作用，提交时必须被过滤掉，否则会把字符串 key 当权限 id 传给后端。

```vue
function buildTree(list) {
  const groups = [
    { key: 'g-menu', label: '菜单权限', children: [] },
    { key: 'g-btn', label: '按钮权限', children: [] },
    { key: 'g-api', label: '接口权限', children: [] }
  ]
  for (const p of list) {
    const idx = p.permType === 1 ? 0 : p.permType === 2 ? 1 : 2
    groups[idx].children.push({
      key: `p-${p.id}`,
      id: p.id,
      label: `${p.permName}（${p.permCode}）`
    })
  }
  return groups.filter((g) => g.children.length > 0)
}
```

图5 权限树分组构建（web/src/views/RolePermission.vue）

**回显与保存：**打开抽屉时并行发两个请求：权限点全量列表（pageSize=200，一次取完）与该角色已授权标识（GET /roles/:id/permissions）。拿到数据后先渲染树，再在 nextTick 里用 setCheckedKeys 勾上已有权限点——顺序不能反，树还没渲染完时调用 setCheckedKeys 会被静默丢弃。保存时把 getCheckedKeys 与 getHalfCheckedKeys 合并，只保留 p- 前缀的项并转成数字，整体 PUT 给后端由事务替换 role_permission。

```vue
async function openGrant(row) {
  current.value = row
  drawerVisible.value = true
  permLoading.value = true
  try {
    // 权限点总量不大，一次取全部；角色已授权标识用于回显
    const [permPage, owned] = await Promise.all([
      listPermissions({ page: 1, pageSize: 200 }),
      getRolePermissions(row.id)
    ])
    treeData.value = buildTree(permPage.list || [])
    await nextTick()
    const keys = (owned || []).map((id) => `p-${id}`)
    treeRef.value?.setCheckedKeys(keys, false)
    checkedCount.value = keys.length
  } catch (e) {
    treeData.value = []
  } finally {
    permLoading.value = false
  }
}
```

function collectChecked() {
  // 分组节点只是展示用，真正提交的只有叶子上的权限点
  const all = [
    ...(treeRef.value?.getCheckedKeys(false) || []),
    ...(treeRef.value?.getHalfCheckedKeys() || [])

}

### 12.5 运营数据看板页

**页面结构：**顶部四张概览卡片（用户总数、今日活跃、今日操作、失败操作），下面一张卡片里纵向排两张图：用户增长图（柱：当日新增 / 线：累计用户）与用户活跃度图（活跃用户、登录次数、操作总量三条折线）。右上角“近 7 天 / 近 30 天”单选按钮控制时间窗口，切换后四卡与两张图一起重取。

**双轴图的做法：**新增人数与累计用户量级差得多（前者每天个位数、后者是累计值），放在同一 Y 轴会把柱子压成一条线。所以用户增长图用两个 Y 轴：左轴给柱状图（新增），右轴给折线（累计），两组数据共享同一 X 轴日期，series 里用 yAxisIndex 指定归属。折线开 smooth、柱子限宽 22px，避免日期一多就挤成一块色块；天数大于 15 时 X 轴标签自动旋转 45 度。

```vue
async function loadGrowth() {
  const data = await getUserGrowth({ days: days.value, granularity: 'day' })
  growthChart.setOption({
    tooltip: { trigger: 'axis' },
    legend: { data: ['新增用户', '累计用户'] },
    grid: { left: 48, right: 24, top: 48, bottom: 32 },
    xAxis: { type: 'category', data: data.xAxis, axisLabel: { rotate: days.value > 15 ? 45 : 0 } },
    yAxis: [
      { type: 'value', name: '新增', minInterval: 1 },
      { type: 'value', name: '累计', minInterval: 1 }
    ],
    series: [
      {
        name: '新增用户',
        type: 'bar',
        barMaxWidth: 22,
        data: data.newUsers,
        itemStyle: { color: '#4E79A7' }
      },
      {
        name: '累计用户',
        type: 'line',
        yAxisIndex: 1,
        smooth: true,
        symbol: 'circle',
        symbolSize: 5,
        data: data.totalUsers,
        itemStyle: { color: '#F28E2B' }
      }
    ]
  })
}
```

onMounted(() => {
