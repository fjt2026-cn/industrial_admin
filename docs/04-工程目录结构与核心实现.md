## 2 各目录职责与边界约定

| 目录 | 职责 | 关键约定 |
| --- | --- | --- |
| config | 从环境变量读取端口、数据库、JWT 参数，产出全局配置对象 | 密钥只走环境变量，不进代码库；DSN 必须带 `parseTime=True&loc=Local` |
| db | 建立 GORM 连接、设置连接池、提供全局句柄 | 只有 `db` 包能赋值 `DB` 变量；连接池上限防止并发压垮数据库 |
| model | 定义表结构映射、字段标签、表名 | 一个结构体对应一张表；`password_hash` 加 `json:"-"` 防止序列化泄露 |
| controller | 绑定并校验请求参数、调用 service、输出统一响应 | 不写 SQL、不写业务规则；失败一律走 `response.Error` |
| service | 业务规则、事务边界、跨表聚合 | 事务只在 service 开启；返回 `*utils.AppError` 表达可预期错误 |
| middleware | 鉴权、鉴权后的权限校验、跨域、异常捕获、操作留痕 | 中断请求用 `response.Abort`，禁止直接 `c.JSON` 后继续执行 |
| routes | 路由分组、公开/受保护划分、权限编码挂载 | 公开接口只放登录；其余全部进受保护组 |
| response | 统一响应结构与错误码 | 全项目只允许这一处拼装 `{code,message,data}` |
| utils | 与业务无关的通用工具 | 不反向依赖 controller/service/model，避免循环引用 |

依赖方向固定为：`routes → controller → service → model → db`，`response`、`utils` 为横向公共包，任何层都可引用但不能反向依赖上层。

## 3 一次请求的完整链路

```text
客户端(Axios)
   │  HTTP 请求 + Authorization: Bearer <token>
   ▼
Gin 引擎
   ├── gin.Logger        访问日志
   ├── Recovery          捕获 panic，转统一响应
   ├── CORS              跨域响应头、OPTIONS 直接返回 204
   ▼
路由分组 /api/v1
   ├── 公开组：POST /auth/login
   └── 受保护组
        ├── Auth         解析并校验令牌 → 写入 ctx_user_id
        ├── OperationLog 记录写操作耗时与结果（响应后异步落库）
        ├── RequirePerm  校验权限编码 → 无权限返回 40300
        ▼
     Controller  参数绑定与校验
        ▼
     Service     业务规则 + 事务
        ▼
     GORM → MySQL 8.0（industrial_admin）
        ▼
     response.OK / Page / Fail
```

## 4 统一响应封装

### 4.1 错误码定义（response/code.go）

```go
package response

import "net/http"

// 业务错误码：与前端拦截器约定一致，0 表示成功
const (
	CodeSuccess      = 0
	CodeParamInvalid = 40001
	CodeUnauthorized = 40100
	CodeForbidden    = 40300
	CodeNotFound     = 40400
	CodeConflict     = 40900
	CodeServerError  = 50000
)

// HTTPStatus 业务码到 HTTP 状态码的映射
func HTTPStatus(code int) int {
	switch code {
	case CodeSuccess:
		return http.StatusOK
	case CodeParamInvalid:
		return http.StatusBadRequest
	case CodeUnauthorized:
		return http.StatusUnauthorized
	case CodeForbidden:
		return http.StatusForbidden
	case CodeNotFound:
		return http.StatusNotFound
	case CodeConflict:
		return http.StatusConflict
	default:
		return http.StatusInternalServerError
	}
}
```

### 4.2 响应结构与输出函数（response/response.go）

```go
package response

import (
	"errors"
	"net/http"
	"time"

	"github.com/gin-gonic/gin"

	"industrial_admin/utils"
)

// Body 统一响应结构：{code, message, data}
type Body struct {
	Code      int    `json:"code"`
	Message   string `json:"message"`
	Data      any    `json:"data"`
	Timestamp int64  `json:"timestamp"`
}

// PageData 分页返回体，前端表格组件直接消费
type PageData struct {
	List     any   `json:"list"`
	Total    int64 `json:"total"`
	Page     int   `json:"page"`
	PageSize int   `json:"pageSize"`
}

// OK 成功返回
func OK(c *gin.Context, data any) {
	c.JSON(http.StatusOK, Body{
		Code:      CodeSuccess,
		Message:   "ok",
		Data:      data,
		Timestamp: time.Now().UnixMilli(),
	})
}

// Success 与 OK 等价，保留两个命名便于语义表达
func Success(c *gin.Context, data any) { OK(c, data) }

// Page 分页返回
func Page(c *gin.Context, list any, total int64, page, pageSize int) {
	OK(c, PageData{List: list, Total: total, Page: page, PageSize: pageSize})
}

// Abort 失败返回，用于中间件中断请求
func Abort(c *gin.Context, code int, message string) {
	c.AbortWithStatusJSON(HTTPStatus(code), Body{
		Code:      code,
		Message:   message,
		Data:      nil,
		Timestamp: time.Now().UnixMilli(),
	})
}

// Fail 失败返回，用于控制器
func Fail(c *gin.Context, code int, message string) {
	c.JSON(HTTPStatus(code), Body{
		Code:      code,
		Message:   message,
		Data:      nil,
		Timestamp: time.Now().UnixMilli(),
	})
}

// Error 统一处理业务错误：AppError 按其错误码返回，其余按服务器内部错误处理
func Error(c *gin.Context, err error) {
	var ae *utils.AppError
	if errors.As(err, &ae) {
		Fail(c, ae.Code, ae.Message)
		return
	}
	Fail(c, CodeServerError, "服务器内部错误")
}
```

## 5 全局异常处理

异常处理分三层：业务层用 `AppError` 表达可预期错误，控制器用 `response.Error` 统一翻译，进程级用 `Recovery` 兜底 panic。

### 5.1 业务异常类型（utils/error.go）

```go
package utils

import "fmt"

// AppError 可预期的业务错误，携带业务码与可直接展示的提示
type AppError struct {
	Code    int
	Message string
	Err     error
}

func (e *AppError) Error() string {
	if e.Err != nil {
		return fmt.Sprintf("%s: %v", e.Message, e.Err)
	}
	return e.Message
}

func (e *AppError) Unwrap() error { return e.Err }

func NewAppError(code int, message string) *AppError {
	return &AppError{Code: code, Message: message}
}

func WrapAppError(code int, message string, err error) *AppError {
	return &AppError{Code: code, Message: message, Err: err}
}
```

### 5.2 进程级兜底（middleware/recovery.go）

```go
package middleware

import (
	"log"
	"runtime/debug"

	"github.com/gin-gonic/gin"

	"industrial_admin/response"
)

// Recovery 全局异常处理：捕获 panic、打印堆栈、返回统一结构，进程不退出
func Recovery() gin.HandlerFunc {
	return gin.CustomRecovery(func(c *gin.Context, err any) {
		log.Printf("panic recovered: %v\n%s", err, debug.Stack())
		response.Abort(c, response.CodeServerError, "服务器内部错误，请联系管理员")
	})
}
```

### 5.3 控制器中的统一出口

控制器不判断错误类型，全部交给 `response.Error`：

```go
list, total, err := h.svc.List(&q)
if err != nil {
	response.Error(c, err)
	return
}
response.Page(c, list, total, q.Page, q.PageSize)
```

这样新增错误场景时，只需在 service 返回 `utils.NewAppError(码, 提示)`，接口输出自动保持一致。

### 5.4 异常处理覆盖的错误场景

| 场景 | 处理位置 | 输出 |
| --- | --- | --- |
| 参数缺失或格式错误 | controller 绑定校验 | 400 / 40001 |
| 账号或口令错误、令牌过期 | service、middleware.Auth | 401 / 40100 |
| 连续 5 次口令错误 | service 锁定账号 10 分钟 | 401 / 40100 |
| 账号被停用或软删除 | middleware.Auth 二次校验 | 401 / 40100 |
| 权限不足 | middleware.RequirePerm | 403 / 40300，并写一条失败日志 |
| 记录不存在 | service 查询判断 | 404 / 40400 |
| 账号、角色、部门编码重复 | service 唯一性校验 | 409 / 40900 |
| 数据库异常、未预期错误 | utils.WrapAppError | 500 / 50000 |
| 运行时 panic（空指针、数组越界等） | middleware.Recovery | 500 / 50000，进程不退出 |

## 6 main.go 完整代码

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"

	"industrial_admin/config"
	"industrial_admin/db"
	"industrial_admin/routes"
)

// 入口：加载配置 → 初始化数据库 → 注册路由 → 启动 HTTP 服务 → 优雅退出
func main() {
	cfg := config.Load()

	if err := db.Init(cfg); err != nil {
		log.Fatalf("数据库初始化失败: %v", err)
	}
	defer func() {
		if err := db.Close(); err != nil {
			log.Printf("关闭数据库连接失败: %v", err)
		}
	}()

	// 自动迁移仅用于开发阶段同步表结构；正式交付以 SQL 脚本建表
	if cfg.App.Mode == "debug" {
		if err := db.AutoMigrate(); err != nil {
			log.Printf("自动迁移失败（可改用 SQL 脚本建表）: %v", err)
		}
	}

	engine := routes.New(cfg)

	srv := &http.Server{
		Addr:           ":" + cfg.App.Port,
		Handler:        engine,
		ReadTimeout:    10 * time.Second,
		WriteTimeout:   10 * time.Second,
		IdleTimeout:    60 * time.Second,
		MaxHeaderBytes: 1 << 20,
	}

	go func() {
		log.Printf("%s 已启动，监听 :%s（mode=%s）", cfg.App.Name, cfg.App.Port, cfg.App.Mode)
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Fatalf("服务启动失败: %v", err)
		}
	}()

	// 信号监听：Ctrl+C 或 kill 时先关闭监听，再等待在途请求结束
	quit := make(chan os.Signal, 1)
	signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
	<-quit
	fmt.Println("收到退出信号，正在关闭服务...")

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	if err := srv.Shutdown(ctx); err != nil {
		log.Printf("优雅关闭超时，强制退出: %v", err)
	}
	log.Println("服务已退出")
}
```

入口设计要点：

1. 配置先于一切，数据库初始化失败立即 `log.Fatalf` 退出，避免带病启动。
2. `defer db.Close()` 保证进程结束前释放连接池。
3. 自动迁移只在 `APP_MODE=debug` 时执行，正式环境以 SQL 脚本建表，防止迁移改动生产表结构。
4. 用 `http.Server` 显式设置超时，避免慢请求长期占用连接。
5. 监听 `SIGINT/SIGTERM`，先停止接收新请求，再用 5 秒超时等待在途请求结束。

## 10 新增一个业务模块的固定步骤

1. `model/` 下新增结构体，字段与库表一致，口令类字段加 `json:"-"`。
2. `service/` 下新增业务方法，事务在此层开启，错误用 `utils.NewAppError` 表达。
3. `controller/` 下新增处理器，只做参数绑定、调 service、`response.OK/Page/Error`。
4. `routes/routes.go` 在受保护组注册路径，并挂对应权限编码。
5. 在 `permission` 表补充权限点，并在 `role_permission` 给对应角色授权。

## 11 约定与注意事项

1. 统一响应只在 `response` 包拼装，其他位置不得自行 `c.JSON` 拼 `{code,message,data}`。
2. 口令只存 bcrypt 哈希（`password_hash` 单列，盐内嵌），接口与日志均不输出明文。
3. 软删除依赖 `gorm.DeletedAt`；删除用户时同步改写 `username`，避免唯一索引冲突导致同名账号无法重建。
4. 写操作由 `middleware.OperationLog` 自动留痕，日志写入失败不阻断业务；查询请求不记日志，避免日志表膨胀。
5. 列表接口统一走 `utils.PageQuery`，单页上限 50，防止一次拉全表。
6. `RequirePerm` 在每次请求做一次联表判权；若并发上升，可对“用户-权限并集”加进程内缓存，授权变更时失效。
7. 生产环境必须替换 `JWT_SECRET`、关闭 `APP_MODE=debug`、关闭自动迁移，并为数据库账号使用最小权限。
