## 7 用户登录与鉴权模块

登录模块是整个系统的入口，也是权限控制的第一道闸门：它把“账号口令”换成“令牌”，后续所有业务接口都以令牌识别身份。模块按 MVC 分层拆成五段——模型定义数据形态、控制器只做参数接收与响应、业务层承担校验与签发、中间件负责拦截未登录请求、路由负责公开组与受保护组的划分。本章按这一调用顺序给出实现，并附接口文档，供实训报告与前后端联调使用。

**一次登录请求的处理链路：**POST /api/v1/auth/login → 控制器参数校验 → 业务层查账号、bcrypt 比对、失败计数与锁定、签发 JWT、查询权限与菜单 → 写操作日志 → 统一响应返回令牌；后续请求携带 Authorization: Bearer <token> → 鉴权中间件解析并校验 → 注入用户上下文 → 进入业务处理。

### 7.1 用户模型

模型只做字段映射，不承担业务判断。口令字段命名为 PasswordHash 并标注 json:"-"，保证序列化到前端时绝不出现哈希值；Status 用 int8 表示启用状态，LoginFailCount 与 LockUntil 支撑失败锁定策略；DeptID 用指针类型，区分“未分配部门”与“部门编号为 0”。

```go
package model

import (
	"time"

	"gorm.io/gorm"
)

// User 用户表：口令只存 bcrypt 哈希，字段与库表一一对应
type User struct {
	ID             uint64         `gorm:"primaryKey;autoIncrement" json:"id"`
	Username       string         `gorm:"size:50;uniqueIndex;not null" json:"username"`
	PasswordHash   string         `gorm:"size:100;not null" json:"-"`
	RealName       string         `gorm:"size:50;not null" json:"realName"`
	Email          string         `gorm:"size:100" json:"email"`
	Phone          string         `gorm:"size:20" json:"phone"`
	DeptID         *uint64        `gorm:"index" json:"deptId"`
	Status         int8           `gorm:"not null;default:1;index" json:"status"`
	LoginFailCount int            `gorm:"not null;default:0" json:"-"`
	LockUntil      *time.Time     `json:"-"`
	LastLoginAt    *time.Time     `gorm:"index" json:"lastLoginAt"`
	LastLoginIP    string         `gorm:"column:last_login_ip;size:45" json:"lastLoginIp"`
	Remark         string         `gorm:"size:255" json:"remark"`
	CreatedAt      time.Time      `json:"createdAt"`
	UpdatedAt      time.Time      `json:"updatedAt"`
	DeletedAt      gorm.DeletedAt `gorm:"index" json:"-"`
	Dept           *Dept          `gorm:"foreignKey:DeptID" json:"dept,omitempty"`
}

// TableName 表名为保留字，GORM 会自动加反引号
func (User) TableName() string { return "user" }
```

### 7.2 控制器层：参数接收与响应

控制器只做三件事：绑定并校验入参、调用业务层、按统一格式输出。参数校验用 Gin 的 binding 标签完成，账号限长 50 字符（与表字段一致），口令限长 72 字节（与 bcrypt 输入上限一致），并在入口处去掉账号首尾空格，避免用户复制粘贴带入的空格导致“明明输入正确却登录失败”。校验失败统一返回 400，不逐字段回显，防止攻击者借提示信息判断字段规则。

```go
package controller

import (
	"strings"

	"github.com/gin-gonic/gin"
	"gorm.io/gorm"

	"industrial_admin/config"
	"industrial_admin/middleware"
	"industrial_admin/response"
	"industrial_admin/service"
)

type AuthController struct{ svc *service.AuthService }

func NewAuthController(cfg *config.Config, database *gorm.DB) *AuthController {
	return &AuthController{svc: service.NewAuthService(database, cfg)}
}

// Login 登录接口：POST /api/v1/auth/login
func (h *AuthController) Login(c *gin.Context) {
	var req struct {
		Username string `json:"username" binding:"required,max=50"`
		Password string `json:"password" binding:"required,max=72"`
	}
	if err := c.ShouldBindJSON(&req); err != nil {
		// 只提示“不能为空或长度超限”，不回显具体字段，避免为探测者提供信息
		response.Fail(c, response.CodeParamInvalid, "账号与口令不能为空，且长度不得超过限制")
		return
	}

	res, err := h.svc.Login(strings.TrimSpace(req.Username), req.Password, c.ClientIP())
	if err != nil {
		response.Error(c, err)
		return
	}
	response.OK(c, res)
}

// Profile 当前用户信息与菜单：GET /api/v1/auth/profile
func (h *AuthController) Profile(c *gin.Context) {
	uid := middleware.CurrentUserID(c)
	info, perms, menus, err := h.svc.Profile(uid)
	if err != nil {
		response.Error(c, err)
		return
	}
	response.OK(c, gin.H{"user": info, "perms": perms, "menus": menus})
}
```

### 7.3 业务层：口令比对、锁定与签发

**口令比对：**调用 utils.VerifyPassword 用 bcrypt 从哈希中取盐重算摘要做常量时间比较，数据库内不存在明文口令；账号不存在与口令错误返回同一句提示，避免通过响应差异枚举出系统内已注册的账号。

**失败锁定：**连续 5 次口令错误即锁定 10 分钟，锁定期内直接拒绝并提示解锁时间；锁定时刻同时清零计数，避免解锁后立即再次触发。登录成功后更新最近登录时间与 IP，为后续活跃度统计提供数据。

**令牌与日志：**校验通过后签发 JWT，载荷只含用户标识与账号，有效期由配置决定；随后一次性查出用户信息、权限编码集合与菜单树随令牌返回，前端拿到响应即可渲染首页，不必二次请求。登录成功与各类失败情形均写入一条操作日志，成功记 result=1，失败记 result=0 并附原因，登录接口位于公开路由组、没有统一留痕中间件，因此这段日志在业务层内显式写入。

```go
package service

import (
	"errors"
	"fmt"
	"time"

	"gorm.io/gorm"

	"industrial_admin/config"
	"industrial_admin/model"
	"industrial_admin/response"
	"industrial_admin/utils"
)

// 登录策略常量，正式环境建议改从 sys_config 读取
const (
	maxLoginFail = 5
	lockMinutes  = 10
)

type AuthService struct {
	db  *gorm.DB
	cfg *config.Config
}

func NewAuthService(database *gorm.DB, cfg *config.Config) *AuthService {
	return &AuthService{db: database, cfg: cfg}
}

type UserInfo struct {
	ID       uint64   `json:"id"`
	Username string   `json:"username"`
	RealName string   `json:"realName"`
	DeptID   *uint64  `json:"deptId"`
	DeptName string   `json:"deptName"`
	Roles    []string `json:"roles"`
}

type LoginResult struct {
	Token     string             `json:"token"`
	ExpiresAt int64              `json:"expiresAt"`
	User      UserInfo           `json:"user"`
	Perms     []string           `json:"perms"`
	Menus     []*utils.TreeNode  `json:"menus"`
}

// recordLogin 登录留痕：成功与失败都落一条操作日志，供审计与锁定排查
func (s *AuthService) recordLogin(userID uint64, username string, result int8, msg, ip string) {
	entry := model.OperationLog{
		Username: username,
		Module:   "登录鉴权",
		Action:   "登录",
		Method:   "POST",
		URL:      "/api/v1/auth/login",
		IP:       ip,
		Result:   result,
		ErrorMsg: msg,
	}
	if userID != 0 {
		uid := userID
		entry.UserID = &uid
	}
	// 日志失败不影响登录主流程
	s.db.Create(&entry)
}

// Login 校验账号口令、处理锁定计数、签发令牌并返回菜单与权限
func (s *AuthService) Login(username, password, ip string) (*LoginResult, error) {
	var u model.User
	err := s.db.Where("username = ?", username).First(&u).Error
	if err != nil {
		if errors.Is(err, gorm.ErrRecordNotFound) {
			s.recordLogin(0, username, 0, "账号不存在", ip)
			return nil, utils.NewAppError(response.CodeUnauthorized, "账号或口令错误")
		}
		return nil, utils.WrapAppError(response.CodeServerError, "登录失败", err)
	}

	if u.LockUntil != nil && u.LockUntil.After(time.Now()) {
		s.recordLogin(u.ID, u.Username, 0, "账号已锁定", ip)
		return nil, utils.NewAppError(response.CodeUnauthorized,
			fmt.Sprintf("账号已锁定，请于 %s 后重试", u.LockUntil.Format("15:04:05")))
	}

	if !utils.VerifyPassword(u.PasswordHash, password) {
		fail := u.LoginFailCount + 1
		updates := map[string]any{"login_fail_count": fail}
		if fail >= maxLoginFail {
			updates["lock_until"] = time.Now().Add(lockMinutes * time.Minute)
			updates["login_fail_count"] = 0
		}
		s.db.Model(&model.User{}).Where("id = ?", u.ID).Updates(updates)
		s.recordLogin(u.ID, u.Username, 0, "账号或口令错误", ip)
		return nil, utils.NewAppError(response.CodeUnauthorized, "账号或口令错误")
	}

	if u.Status != 1 {
		s.recordLogin(u.ID, u.Username, 0, "账号已停用", ip)
		return nil, utils.NewAppError(response.CodeForbidden, "账号已停用，请联系管理员")
	}

	now := time.Now()
	s.db.Model(&model.User{}).Where("id = ?", u.ID).Updates(map[string]any{
		"login_fail_count": 0,
		"lock_until":       nil,
		"last_login_at":    now,
		"last_login_ip":    ip,
	})

	token, exp, err := utils.GenerateToken(s.cfg, u.ID, u.Username)
	if err != nil {
		return nil, utils.WrapAppError(response.CodeServerError, "签发令牌失败", err)
	}

	info, perms, menus, err := s.Profile(u.ID)
	if err != nil {
		return nil, err
	}

	s.recordLogin(u.ID, u.Username, 1, "", ip)

	return &LoginResult{Token: token, ExpiresAt: exp, User: *info, Perms: perms, Menus: menus}, nil
}

// Profile 返回用户信息、权限编码集合与菜单树（多角色取并集）
func (s *AuthService) Profile(userID uint64) (*UserInfo, []string, []*utils.TreeNode, error) {
	var u model.User
	if err := s.db.Preload("Dept").Where("id = ?", userID).First(&u).Error; err != nil {
		return nil, nil, nil, utils.WrapAppError(response.CodeNotFound, "用户不存在", err)
	}

	info := &UserInfo{ID: u.ID, Username: u.Username, RealName: u.RealName, DeptID: u.DeptID}
	if u.Dept != nil {
		info.DeptName = u.Dept.DeptName
	}

	var roleNames []string
	if err := s.db.Table("role r").
		Joins("JOIN user_role ur ON ur.role_id = r.id").
		Where("ur.user_id = ? AND r.status = 1 AND r.deleted_at IS NULL", userID).
		Pluck("r.role_name", &roleNames).Error; err != nil {
		return nil, nil, nil, utils.WrapAppError(response.CodeServerError, "查询角色失败", err)
	}
	info.Roles = roleNames

	perms := make([]string, 0)
	if err := s.db.Table("permission p").
		Joins("JOIN role_permission rp ON rp.perm_id = p.id").
		Joins("JOIN user_role ur ON ur.role_id = rp.role_id").
		Where("ur.user_id = ? AND p.status = 1 AND p.deleted_at IS NULL", userID).
		Distinct().Pluck("p.perm_code", &perms).Error; err != nil {
		return nil, nil, nil, utils.WrapAppError(response.CodeServerError, "查询权限失败", err)
	}

	var menus []model.Permission
	if err := s.db.Table("permission p").
		Joins("JOIN role_permission rp ON rp.perm_id = p.id").
		Joins("JOIN user_role ur ON ur.role_id = rp.role_id").
		Where("ur.user_id = ? AND p.status = 1 AND p.perm_type = 1 AND p.deleted_at IS NULL", userID).
		Distinct().Order("p.sort_no").Find(&menus).Error; err != nil {
		return nil, nil, nil, utils.WrapAppError(response.CodeServerError, "查询菜单失败", err)
	}

	nodes := make([]*utils.TreeNode, 0, len(menus))
	for _, p := range menus {
		var parent uint64
		if p.ParentID != nil {
			parent = *p.ParentID
		}
		nodes = append(nodes, &utils.TreeNode{
			ID: p.ID, ParentID: parent, Name: p.PermName,
			Code: p.PermCode, Type: p.PermType, SortNo: p.SortNo,
		})
	}

	return info, perms, utils.BuildTree(nodes), nil
}
```

### 7.4 JWT 鉴权中间件

中间件从 Authorization 头取 Bearer 令牌，先判断格式再解析签名与过期时间，失败即以 401 终止请求链；解析通过后再回查一次数据库，确认账号仍存在且状态为启用——令牌有效不等于账号可用，停用或删除的账号必须立即失效。校验结果写入请求上下文，供控制器与权限中间件读取。

```go
package middleware

import (
	"errors"
	"strings"

	"github.com/gin-gonic/gin"
	"gorm.io/gorm"

	"industrial_admin/config"
	"industrial_admin/db"
	"industrial_admin/model"
	"industrial_admin/response"
	"industrial_admin/utils"
)

// 上下文键，供控制器与权限中间件读取
const (
	CtxUserID   = "ctx_user_id"
	CtxUsername = "ctx_username"
)

// Auth 鉴权：解析 Bearer 令牌，校验签名、过期与用户状态
func Auth(cfg *config.Config) gin.HandlerFunc {
	return func(c *gin.Context) {
		header := c.GetHeader("Authorization")
		if header == "" || !strings.HasPrefix(header, "Bearer ") {
			response.Abort(c, response.CodeUnauthorized, "未登录或令牌缺失")
			return
		}
		tokenStr := strings.TrimPrefix(header, "Bearer ")
		claims, err := utils.ParseToken(cfg, tokenStr)
		if err != nil {
			// 区分“过期”与“无效”：过期提示用户重新登录更友好
			msg := "令牌无效，请重新登录"
			if errors.Is(err, utils.ErrTokenExpired) {
				msg = "登录已失效，请重新登录"
			}
			response.Abort(c, response.CodeUnauthorized, msg)
			return
		}

		// 令牌有效不代表账号仍可用：停用或删除后即时失效
		var u model.User
		if err := db.DB.Where("id = ?", claims.UserID).First(&u).Error; err != nil {
			if err == gorm.ErrRecordNotFound {
				response.Abort(c, response.CodeUnauthorized, "账号不存在")
				return
			}
			response.Abort(c, response.CodeServerError, "服务器内部错误")
			return
		}
		if u.Status != 1 {
			response.Abort(c, response.CodeUnauthorized, "账号已停用，请联系管理员")
			return
		}

		c.Set(CtxUserID, u.ID)
		c.Set(CtxUsername, u.Username)
		c.Next()
	}
}

// CurrentUserID 从上下文取当前用户标识
func CurrentUserID(c *gin.Context) uint64 {
	if v, ok := c.Get(CtxUserID); ok {
		if id, ok := v.(uint64); ok {
			return id
		}
	}
	return 0
}

// CurrentUsername 从上下文取当前账号
func CurrentUsername(c *gin.Context) string {
	if v, ok := c.Get(CtxUsername); ok {
		if name, ok := v.(string); ok {
			return name
		}
	}
	return ""
}
```

### 7.5 路由注册

路由把公开接口与受保护接口分成两组：登录接口单独放在公开组；其余接口统一挂载鉴权中间件与操作留痕中间件，再按需叠加权限点中间件。分组写法的好处是新增业务接口时只要放进受保护组，就自动获得鉴权，不会因为漏写中间件而暴露接口。

```go
package routes

import (
	"github.com/gin-gonic/gin"

	"industrial_admin/config"
	"industrial_admin/controller"
	"industrial_admin/db"
	"industrial_admin/middleware"
	"industrial_admin/response"
)

// New 组装路由树：公开组（登录）与受保护组（业务）分离
func New(cfg *config.Config) *gin.Engine {
	if cfg.App.Mode == "release" {
		gin.SetMode(gin.ReleaseMode)
	}

	r := gin.New()
	r.Use(gin.Logger(), middleware.Recovery(), middleware.CORS())
	r.NoRoute(func(c *gin.Context) {
		response.Fail(c, response.CodeNotFound, "接口不存在")
	})

	authCtl := controller.NewAuthController(cfg, db.DB)
	userCtl := controller.NewUserController(db.DB)
	roleCtl := controller.NewRoleController(db.DB)
	deptCtl := controller.NewDeptController(db.DB)
	cfgCtl := controller.NewConfigController(db.DB)
	dashCtl := controller.NewDashboardController(db.DB)
	logCtl := controller.NewLogController(db.DB)

	api := r.Group("/api/v1")
	{
		api.POST("/auth/login", authCtl.Login)
	}

	// 受保护组：先鉴权，再按接口挂权限点，最后统一留痕
	priv := api.Group("")
	priv.Use(middleware.Auth(cfg), middleware.OperationLog(db.DB))
	{
		priv.GET("/auth/profile", authCtl.Profile)

		users := priv.Group("/users")
		{
			users.GET("", middleware.RequirePerm("api:user:list"), userCtl.List)
			users.POST("", middleware.RequirePerm("user:create"), userCtl.Create)
			users.PUT("/:id", middleware.RequirePerm("user:update"), userCtl.Update)
			users.DELETE("/:id", middleware.RequirePerm("user:delete"), userCtl.Delete)
			users.POST("/:id/password", middleware.RequirePerm("user:resetpwd"), userCtl.ResetPassword)
		}

		roles := priv.Group("/roles")
		{
			roles.GET("", middleware.RequirePerm("sys:role"), roleCtl.List)
			roles.POST("", middleware.RequirePerm("role:grant"), roleCtl.Create)
			roles.GET("/:id/permissions", middleware.RequirePerm("role:grant"), roleCtl.Permissions)
			roles.PUT("/:id/permissions", middleware.RequirePerm("role:grant"), roleCtl.Grant)
		}

		depts := priv.Group("/depts")
		{
			depts.GET("/tree", deptCtl.Tree)
			depts.POST("", middleware.RequirePerm("dept:create"), deptCtl.Create)
		}

		configs := priv.Group("/configs")
		{
			configs.GET("", cfgCtl.List)
			configs.PUT("/:id", middleware.RequirePerm("config:update"), cfgCtl.Update)
		}

		priv.GET("/dashboard/overview", dashCtl.Overview)
		priv.GET("/logs", middleware.RequirePerm("audit:log"), logCtl.List)
	}

	return r
}
```

### 7.6 接口文档

下表为登录模块涉及的两个接口，可直接用于前后端联调与报告附录。所有接口响应体均为统一结构{code, message, data, timestamp}，表中“出参示例”给出 data 与关键字段。

**表1 登录模块接口清单**

| URL | 请求方式 | 鉴权要求 | 功能说明 |
| :--- | :--: | :--: | :--- |
| /api/v1/auth/login | POST | 公开 | 账号口令登录，签发 JWT 并返回用户信息、权限编码与菜单树 |
| /api/v1/auth/profile | GET | 需登录 | 按令牌返回当前用户信息、权限编码与菜单树，用于刷新页面后恢复状态 |

**表2 登录接口入参（application/json）**

| 字段 | 类型 | 必填 | 约束 | 说明 |
| :--- | :--: | :--: | :--- | :--- |
| username | string | 是 | 非空，≤50 字符 | 登录账号，提交前去除首尾空格 |
| password | string | 是 | 非空，≤72 字节 | 登录口令，服务端与数据库哈希比对，不落库、不入日志 |

**表3 登录成功出参字段**

| 字段 | 类型 | 说明 |
| :--- | :--: | :--- |
| code | int | 业务码，0 表示成功 |
| data.token | string | JWT 令牌，后续请求置于 Authorization: Bearer 头 |
| data.expiresAt | int64 | 令牌过期时间（毫秒时间戳） |
| data.user | object | 用户信息：id、username、realName、deptId、deptName、roles |
| data.perms | string[] | 权限编码并集，如 api:user:list、user:create |
| data.menus | object[] | 菜单树，含 id、parentId、name、code、type、sortNo、children |
| timestamp | int64 | 服务端响应时间戳（毫秒） |

### 7.8 本章小结

登录模块的实现要点可归纳为四句话：口令只在内存中以明文出现一次，落库的是 bcrypt 哈希；令牌只承载身份标识，权限与菜单每次按库实时计算，保证授权变更即时生效；鉴权中间件不只校验签名，还回查账号状态；登录成功与失败都留痕，使审计与锁定排查有据可查。后续开发角色授权、用户管理等功能时，身份与权限均从本模块的上下文键获取，不再重复解析令牌。
